## สรุปใจความสำคัญ (Executive Summary)
CyanVoxel สร้าง "vault ในฝัน" ด้วย 3 เสาหลัก: **การตกแต่งที่ลึกถึงกระดูก** (CSS snippets มากมาย), **plugins ที่คัดสรร** (17 ตัว เน้นงานประจำวัน), และ **ระบบองค์กรลูกผสม** Zettelkasten × PARA × MOCs ที่ยืดหยุ่นตามความต้องการ

## การวิเคราะห์เชิงลึก (Deep Analysis)

### จุดเด่นของระบบ CyanVoxel
- **Theming เป็นเครื่องมือ ไม่ใช่แค่ความสวย** — Notebook Themes (จำลองสมุดจริง) ช่วยเชื่อมการเขียนดิจิทัลกับสนาม; Daily Note Themes 7 สีให้สัญญาณภาพว่าวันนี้เปิดโน้ตถูกตัวหรือไม่; Colored Sidebar ทำให้หา folder เร็วขึ้นด้วยสี
- **ฟอนต์ monospace ตลอดทั้ง vault** — JetBrains Mono Nerd เป็นตัวเลือกที่ทำให้โน้ตดู "โปรแกรมมิ่ง" ใช้ใน terminal/Linux มาก่อน
- **Smart Typography**: สลับ quotes/apostrophes เป็น typographic ตามบริบท — จุดเล็กที่คนเขียนยาวๆ รู้สึกได้ (และกด backspace เพื่อย้อนกลับ)
- **ระบบองค์กรแบบ "สาน" ไม่ใช่ "เลือกข้าง"** — Zettelkasten ดูแล "ความรู้เชิงลึก" (fleeting→literature→permanent + linking) ส่วน PARA ดูแล "ชีวิตจริง" (โปรเจกต์/พื้นที่/ทรัพยากร/คลัง) และ MOC ทำหน้าที่สะพานเชื่อมทั้งสอง

### ข้อสังเกตเชิงลึก
- **"Overkill is a feature"** — เขายอมรับเองว่าธีมมากมายเกินจำเป็น (Manila background สำหรับทุกโน้ต?) แต่ความสนุกในการปรับแต่งทำให้ระบบอยู่รอดระยะยาว — ตรงข้ามกับแนวคิด minimal ที่หลายคนแนะนำ
- **CSS snippets ใช้ class-based ต่อโน้ต** — ไม่รบกวนโน้ตอื่น; เป็นหลักการเดียวกับ [[wiki/concepts/MOC (Map of Content)|MOC]] ที่แยกหน้าที่ชัดเจน
- **ระบบที่ "เติบโต"** — เขาเน้นว่า vault ต้องเปลี่ยนตามความต้องการ ไม่มีสูตรสำเร็จตายตัว

### การเปรียบเทียบกับ vault นี้ (Krit Wiki)
| มิติ | CyanVoxel | Krit Wiki นี้ |
|---|---|---|
| โฟกัส | รูปลักษณ์ + workflow ส่วนตัว | ความรู้เชิงโครงสร้าง (LLM-managed) |
| องค์กร | Zettelkasten × PARA × MOCs | MOCs + categories (AGENTS.md schema) |
| Theming | CSS แบบ manual เยอะมาก | 1 snippet (wiki-beauty.css) + AnuPpuccin |
| Plugins | 17 ตัว (งานคนเดียว) | ~26 ตัว (รวม automation: Linter, Git, Dataview) |
| จุดแข็ง | สนุก/งดงาม/เป็นส่วนตัวสูง | ตรวจสอบอัตโนมัติ (lint), log ทุกการเปลี่ยนแปลง |
